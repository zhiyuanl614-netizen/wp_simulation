# 全耦合映射设计 —— 54 台发电机 ↔ D-town 取水 junction

**模块：** `src/00_muni_wdn/coupling_map.py`　**产出：** `results/muni/coupling_map.{json,csv,png}`
**版本：** v1　**状态：** 映射已生成；下游边界重跑与 N 场景扫描待指令实施。

---

## 1. 耦合原因概述

1. **物理耦合原因（为何要耦合）：** 本市火电机组的循环冷却水**补水均取自市政配水管网**——每台发电机在物理上都"挂接"在某个配水节点上：该节点的供水压头决定补水能否维持（< 28 m 即失效），是冷却水危机的起点。因此作为**一整套城市水-电耦合系统**，**所有 54 台发电机节点（含平衡机）均应有 junction 耦合**，而非仅 3 对。
2. **信息耦合原因（为何耦合点即预警点）：** 市政供水 ICS 对**每个耦合取水节点**监测压头；跌破 28 m 的时刻 `t_fault_i` 既是该机组供水失效时刻、也是跨域早期预警时刻（失效=预警，同一阈值，零时延），驱动电力侧按 `SAET_i` 窗口主动控制。
3. **此前仅 3 对的原因与升级动机：** 原 3 对（J411↔89、J371↔80、J197↔10）服务于"机理揭示 + 对齐参照文献两级案例 + LP 可解"，属指定配对（`paper_outline.md` §7 已如实声明）。全耦合消除"指定配对代表性"问题，使城市级结论不依赖人为挑点，并自然支撑 **N 个耦合节点失效** 的场景扫描。

## 2. 映射规则（v1，确定、可复现）

| 步 | 规则 | 说明 |
|---|---|---|
| 1 | **保留已校验三对** | 89-J411 / 80-J371 / 10-J197，全部既有结果不变 |
| 2 | **基线健康筛选** | 无故障 24 h EPS 全程最小压头 > 32 m 的 junction 方可作取水点（与 `saet_distribution.py` 健康判据一致） |
| 3 | **分层比例抽样** | 按"唯一水源停供后失压时刻"分 Q1(快)/Q2/Q3/Q4(慢)/never(72h 不失压) 五层；51 个新名额按各层节点数占**全网**比例分配（最大余数法），层内按 t_fail 等间距抽取 → 耦合集合的失压分布**复现全网分布** |
| 4 | **确定性配对** | 其余 51 台机按 bus 升序 × 节点按 (t_fail, 名) 升序一一配对；**不隐含容量–位置相关性** |
| 5 | **补水负荷（额定需求）** | `makeup_Lps = clip(0.03·Pmax, 2, 20)` L/s（容量缩放）；保留对 = 20；**不反馈进城市水力**，仅作下游与可供性评估用（依据 §5） |

## 3. 映射结果统计（v1）

- 分层名额（新 51）：Q1=6 / Q2=12 / Q3=10 / Q4=9 / never=14；含保留对后全 54：Q2=13、never=16。
- 耦合节点失压时刻：min 0 / **中位 9.4** / max 67 h；**never = 16 台（29.6%）** ≈ 全网 27.6% —— 分布复现良好。
- 四分位边界：q25/q50/q75 = 3.75 / 9.75 / 13.19 h。
- 空间上各层呈 DMA 分区聚集（快失压点近水源/弱缓冲区，never 点位于强缓冲高区），物理自洽。

## 5. 全耦合边界验证与补水可供性（本轮完成）

动机：把 54 路额定补水反馈进城市水网做仿真接线与一致性核查。发现与决策链：

1. **额定反馈不可行**：D-town 水源出力仅 ~246 L/s；299.7 L/s 额定补水并网使基线耦合节点 min 压头 −12 m，saet 口径分层一致率仅 14.8%。
2. **逐节点 DMA 容量分配不可行**：个体容量不叠加，联合即崩（−10.9 m）。
3. **昼间模式+总量预算可行但破坏分层**：昼间模式（6–22 h=1.0、夜 0.05）可避免夜间恒定负荷翻转泵/水箱调度（恒定模式下即使仅保留三对 60 L/s 也使 J283 饿死至 ~5 m）；保留三对 20 + 容量比例 T=60（合计昼间额定 120 L/s）基线健康（32.5 m），但**任何非零反馈**都耗尽水箱缓冲使 never 层 ~24 h 失压：T=10 一致率 81.5%、T=60 70.4%，且保留 bus10/80 由 never 滑层 —— 与已发布分层矛盾。
4. **最终语义①**：城市水力保持无补水口径（与 saet/coupling_map 完全一致），额定补水作为被评估需求事后按 PDD 份额 `f=sqrt(clip(p/20,0,1))` 评估可供量。

①验证结果：

- 基线：耦合节点 min 压头 **34.0 m**（0 个 ≤32/28 m）；水源出力 246 L/s。
- 一致性：saet 口径 **54/54 = 100%**（分层与 t_fail 精确一致，见 `full_coupling_consistency.csv`）。
- 可供性（boundary 口径 72 h）：全网合计需求 77 682 m³、可供 71 478 m³（**92.0%**）；分层 Q1 55.1% / Q2 81.5% / Q3 98.0% / Q4 99.6% / never 100% —— 失压越快的层，市政备用补水丧失越早，与分层物理自洽；24 h 内完全断供（p≤0）节点 0。

## 6. 耦合规律全节点验证（54/54 通过）

待证规律：市政供水侧节点**只反馈压力水头**（不核对水量能否满足电力侧冷却需求）；压头 **< 28 m 此刻即失效**（补水归零、不能为补水箱补水）；**SAET 自该时刻起算**；且对全部 54 节点成立。

验证脚本 `src/00_muni_wdn/verify_coupling_rule.py`，结果 `results/muni/coupling_rule_verification.{json,csv}`：

| 项 | 方法 | 结果 |
|---|---|---|
| 只反馈压头 | 边界数据每节点仅含 `pressure_m` 轨迹 + 28 m 派生时刻；城市仿真不读电厂需水量 | 54/54 |
| 阈值即刻失效 | 轨迹独立重算 t(<28m) 与存档一致；`make_flow` 在 t_fault 前 >0、后 =0 | 触发 38/54 全过；never 16 节点 72h 内不出现 <28m → 不触发（亦符合规律） |
| SAET 起算 | 以各节点 t_fault_i 跑全链条（补水箱→集水池→NPSH→背压→跳机），SAET = t_trip − t_fault_i | 54/54 |

**附带发现（如实记录）**：54 台中 **35 台 Pg=0**（case 调度点），热负荷≈0 → 循环损失极小（如 bus1 仅 0.0015 m³/s）→ 缓冲数十天，SAET >24h（27 个触发节点中 24 台 Pg=0、3 台 Pg≤19 MW）；这些机组的耦合仅具拓扑/预警意义，不发生冷却级联。有出力机组 SAET 为数值（如 Q2 中位 ~193 min、Q3 中位 ~349 min）。

## 7. 水量账闭合（③′，完成）

闭合脚本 `src/00_muni_wdn/closed_water_balance.py`，结果 `results/muni/closed_water_balance.{json,csv}`：

1. **物理补水口径**：q_phys = 0.453 m³/s@707MW 按 Pmax 缩放；72h 需求 **1 655 179 m³**、PDD 可供 **1 522 135 m³（92.0%）**；分层 Q1 54.9% / Q2 81.7% / Q3 98.3% / Q4 99.8% / never 100%。
2. **城市轨迹驱动电厂链**：补水阀驱动压头 = p(t)−28 m（高位补水箱充填压头需求 = 28 m 阈值的物理来源），取代合成 32→0 阶跃。闭合 SAET（Pg 热负荷）**100% ≥ 已发布合成值**（合成阶跃为保守下界；差值来自市政压头渐降剖面，如 bus89：合成 92 min vs 闭合 1809 min）。
3. **Pmax 热负荷鲁棒变体**：消除 Pg=0 退化，**29/54** 节点在 72h 内跳机（其余 25 个为 never 层，72h 不失压）；各触发层闭合 SAET 中位 ≈ 37–41 h。
4. 结论：松耦合接口（压头代理）给出保守 SAET；闭合水量账确认城市侧可供比例与电厂侧缓冲的尺度自洽，且 28 m 阈值具有充填压头的物理解释。
