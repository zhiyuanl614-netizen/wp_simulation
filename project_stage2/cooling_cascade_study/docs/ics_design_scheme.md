# 工业控制系统（ICS / 信息系统）设置方案（待确认）

**版本：** v0.2（已确认并落地）　**日期：** 2026-07-06

> **确认后的简化（v0.2）：**
> 1. **不考虑检测延时 / 通信丢包 / 漏报**——市政压头跌破阈值即刻可靠预警（零时延）。
> 2. **检测只用市政供水压力（源头信号）**——补水箱、集水池、凝汽器背压均属电力系统内部子系统、彼此存在交互，不作独立监测点；因此 §4 的 B/C 策略与 §5 的可靠性建模**不实现**，只保留"**有无早期预警**"两种情形（WARN / NOWARN）。
**定位：** 在现有 P0–P5+ 项目基础上，加入三级工业控制系统（信息系统），把"早期预警"从**理想化假设**（固定 `t_detect`）升级为**由信息系统内生产生的可解释量**（检测时延 + 通信时延 + 可靠性）。

> 本文件为**方案稿**，确认后再生成代码。参照用户提供的市政供水 ICS 代码（三级 ICS + SQLite 库），并适配到本项目的冷却水—电网耦合场景。

## 1. 为什么要加 ICS —— 与研究目标的关系

研究核心命题：**利用水力慢动态与电力快动态的时序差异，经信息/工控系统提前预警，使电网主动处置。**

现状（P4/P5）：预警被抽象为一个参数 `t_detect`（故障后固定延时电网即知情），预警可靠性（漏报/误报）也是外生概率。

**加入 ICS 后的升级：**

| 现状（理想化） | 加入 ICS 后（内生、可解释） |
|---|---|
| `t_detect` 是给定参数 | `t_detect` = **传感器检测时延 + 三级 ICS 通信/处理时延** 之和，由监测点位置与阈值决定 |
| 预警可靠性是外生概率 | 漏报/误报/时延抖动来自**传感器故障、通信丢包、阈值整定**等 ICS 层真实机制 |
| "预警提前量"是扫描轴 | "预警提前量"由**在哪里监测、用什么判据**决定——变成可设计的工程量 |

**这正是把 P4/P5 的关键自变量"接地"到物理信息系统上**，让"预警价值"的结论有了工程可实现的载体。

## 3. 三级 ICS 职责（适配冷却水场景）

### 第一级：现场 PLC（`FieldPLC`）
- **传感器采样**（带采样周期与可选噪声）：
  - 市政供水压力 `p_muni`（对应 `muni_head`）
  - 高位补水箱水位 `H_tank`
  - 集水池水位 `H_pool`
  - 循环水泵状态/流量 `m_cw`、凝汽器背压 `p_b`
- **本地自动控制**（本项目物理层已含，PLC 层做显式封装）：
  - 补水箱/集水池液位控制阀（滞环/比例）
  - 循环水泵低淹没深度(NPSH)保护跳泵、汽机高背压保护
- 输出：传感器读数 + 执行器状态

### 第二级：SCADA（`SCADA`）
- **数据汇集 + 历史归档**（写入 SQLite）
- **故障检测与告警生成**（核心新增，见 §4）：
  - 阈值判据 / 变化率(趋势)判据
  - 告警分级（正常 / 预警 / 严重）
- **上传**监控数据与告警到调度层

### 第三级：调度中心（`DispatchCenter`）
- **厂级决策**：确认预警→生成"跨域预警信号"
- **跨域链路**：把预警信号（含预警提前量、置信度）传给**电网调度**（对接 `cascade.py` 的 `proactive` 控制器）
- 电网侧据此触发：三级备用预起机 + 速率受限 runback + 预防性切负荷（均已实现）

## 4. 核心创新：预警的"内生化"检测策略

**不同监测点 → 不同检测时延 → 不同预警提前量。** 这把 P4/P5 的"预警提前量"轴变成可设计的工程选择：

| 策略 | 监测量 & 判据 | 检测时刻 | 预警提前量 | 特点 |
|---|---|---|---|---|
| **A 市政压力直检** | `p_muni` 跌破阈值 | 故障后**数秒** | **最大**(≈整个缓冲窗口) | 源头检测，最灵敏；依赖市政侧仪表 |
| **B 补水流量/水箱液位** | 补水流量→0 或 `H_tank` 异常下降 | 故障后**数分钟** | 中等 | 厂内可测，较稳健 |
| **C 集水池液位** | `H_pool` < 预警阈值 | 接近跳泵前 | **最小** | 最晚，接近被动 |
| **D 无 ICS（基线）** | 仅泵跳/背压保护 | 跳机时刻 | 0（被动） | 对照组 |

**科学产出：** 用 ICS 内生地复现 P4/P5 的"预警提前量→韧性"曲线，并回答"**应在哪里、用什么判据监测，才能既灵敏又可靠**"。

---

## 5. 预警可靠性的 ICS 层建模（对接 P5+）

把 P5+ 的外生概率替换为 ICS 层机制：
- **漏报**：传感器故障/离线（`is_fault` 标志）、判据未触发 → 预警不发出 → 电网被动
- **误报**：噪声/扰动导致阈值误触发 → 无故障却预警（记录误报代价）
- **时延抖动**：三级 ICS 通信/处理时延随机 → 预警提前量抖动
- **通信丢包**：跨域链路失败 → 预警丢失

这样 P5+ 的鲁棒策略结论就有了**真实 ICS 参数支撑**（采样周期、通信时延分布、传感器可靠度）。

## 6. 数据库（SQLite，参照用户代码）

沿用参照代码的表结构，适配本项目：

| 表 | 内容 |
|---|---|
| `sensor_data` | 时间, 传感器ID(p_muni/H_tank/H_pool/m_cw/p_b), 值, 单位, 故障标志 |
| `actuator_cmd` | 时间, 执行器ID(补水阀/循环水泵), 状态, 来源 |
| `monitor_status` | 时间, 告警码, 告警信息, 明细 |
| `dispatch_cmd` | 时间, 指令类型, 目标, 值, 来源 |
| `warning_signal`（新增） | 时间, 是否发出预警, 检测策略, 预警提前量估计, 置信度 |
| `network_snapshot` | 时间, 水箱/水池水位, 循环水/背压, 泵状态, 电网频率, 是否主动处置 |

**作用：** 全过程可审计、可回放；P5+ 的漏报/误报统计可直接从库中导出。
