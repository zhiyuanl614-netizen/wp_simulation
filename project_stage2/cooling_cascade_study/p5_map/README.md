# P5 — 全场景韧性图谱与最优预警-处置策略

**阶段目标：** 在 P4 单点对比的基础上，做**二维全场景扫描**（预警提前量 × 故障规模），生成**韧性图谱**，并据此给出**面向调度的最优预警-处置策略**。这是研究目标"量化早期预警的系统韧性优化"的系统化收官。

## 文件

| 文件 | 说明 |
|---|---|
| `resilience_map.py` | 韧性图谱：(预警提前量 × 故障规模) → f_nadir / ΔResilience 热力图 + 临界预警提前量曲线 |
| `optimal_strategy.py` | 最优处置策略：每种故障规模下达到安全阈值所需的最小处置组合（预置备用 + 预防性切负荷）|
| `build_lookup.py` | 预计算 f_nadir 查找表（故障规模×预警提前量×切负荷），供可靠性分析快速插值 |
| `reliability.py` | **预警可靠性/鲁棒策略**：蒙特卡洛评估漏报/时延抖动/误报下各策略的风险分布 |
| `../results/p5_resilience_map.png` | 韧性图谱（核心成果）|
| `../results/p5_critical_leadtime.png` | 临界预警提前量曲线 |
| `../results/p5_optimal_strategy.png` | 最优处置代价曲线 |
| `../results/p5_reliability.png` | 预警不确定下的鲁棒策略风险评估 |
| `../results/p5_summary.json` `p5_strategy.json` `p5_lookup.json` `p5_reliability.json` | 结果数据 |

## 运行

```bash
cd p5_map
python resilience_map.py       # 二维韧性图谱 (~5min)
python optimal_strategy.py     # 最优处置策略 (~9min)
python build_lookup.py         # 预计算查找表 (~12min, 供下一步用)
python reliability.py          # 预警可靠性/鲁棒策略 蒙特卡洛 (秒级, 依赖查找表)
```

> 故障规模 = 市政水网共因影响的机组数量（取 IEEE-118 最大的 1–5 台非平衡机组）。
> 预警提前量 = 被动情形下首台机组跳机时刻 − 预警时刻，通过 `t_detect` 反算。
> 两个主动处置杠杆：**L1 预置/提前起机三级备用**（受预警提前量约束）、**L2 预防性切负荷**（快速但有失负荷代价）。

> **注（v2 水力模型）：** 损失随热负荷变化引入了降额自保护负反馈（见 `models/water_side_model.md` 2b 节），共因机组跳机被拉开、被动韧性整体上移；危险阈值从 3 机上移到 4–5 机。以下为 v2 结果。

## P5 核心结果

### 1. 韧性图谱（`p5_resilience_map.png`）

主动预警下的频率最低点 f_nadir（Hz），横轴预警提前量、纵轴故障规模：

| 故障规模 | 被动 f_nadir | 主动(预置备用,预警≥5min) | 说明 |
|---|---|---|---|
| 1–2 机 | 50.0 | 50.0 | 旋转备用充足，无需预警 |
| 3 机 | 49.5 | 50.0 | 降额自保护使其基本安全 |
| **4 机** | **46.9（崩溃）** | **49.9** | **对预警最敏感——预警价值区** |
| **5 机** | **41.7（崩溃）** | 43+ | 仅预置备用不够，须叠加切负荷 |

### 2. 临界预警提前量 t_lead*（`p5_critical_leadtime.png`）

保证系统安全（f≥49 Hz）所需的**最小预警窗口**：

| 故障规模 | t_lead* | 结论 |
|---|---|---|
| 1–3 机 | ~0（无需）| 备用/降额自保护自足 |
| **4 机** | **仅预警须配合少量切负荷（~6%）** | 预警显著抬升，配少量切负荷达标 |
| 5 机 | 仅预警不可达 | 须叠加预防性切负荷（10–15%）|

### 3. 最优预警-处置策略（`p5_optimal_strategy.png`，核心政策结论）

达到安全所需的**最小预防性切负荷比例**（v2 模型）：

| 故障规模 | 所需最小切负荷 | 说明 |
|---|---|---|
| 3 机 | **0%（仅预置备用）** | 降额自保护 + 备用即可 |
| 4 机 | 切负荷 ~6% | 少量切负荷即达标 |
| 5 机 | 切负荷 10–15% | 大规模缺额，须显著切负荷 |

**关键结论：**
1. **预警可"替代"切负荷**——故障规模越小、预警越早，越能用"预置备用/降额软着陆"替代硬切负荷。3 机故障可完全免切负荷；4 机仅需 ~6%；5 机须 10–15%。
2. **韧性由"预警提前量 × 备用起机能力 × 切负荷"共同决定**，存在**规模临界**：小故障备用/降额自保护自足；4 机是预警"黄金价值区"（被动崩溃→主动安全）；大故障预警可减轻但须叠加切负荷。
3. **runback 必须节奏匹配**（v2 修正）——主动降负荷卸下发电的速率不能快于备用/切负荷补充速率，否则自造缺额、适得其反。"软着陆"是节奏问题。
4. **水力慢动态是预警窗口的物理来源**——P1 表明缓冲时间 t_buffer≈29 min（阶跃）到更长（渐降），**远大于所需临界预警窗口**，说明该预警机制物理可行且裕度充裕。

## P5 扩展 —— 预警可靠性与鲁棒策略（`p5_reliability.png`）

前述结论假设预警"完美"。现实中信息/工控系统(ICS)预警存在**漏报、时延抖动、误报**。本扩展用蒙特卡洛（漏报率 15%、预警提前量 N(8, 3) min、误报率 10%）评估三类策略的**风险分布**：

- **S-Reactive**：纯被动，不依赖预警
- **S-Trust**：完全信任预警——仅预置备用（大故障收到预警才切负荷），漏报时无托底
- **S-Robust**：鲁棒策略——即使不依赖预警也**常备一定托底切负荷**，收到预警再加码

| 故障规模 | 策略 | 期望 f_nadir | 崩溃概率 P(f<47Hz) | 5% 尾部 |
|---|---|---|---|---|
| 4 机 | S-Reactive | 46.95 | 89.1% | 46.91 |
| 4 机 | S-Trust | 49.53 | 15.1% | 46.91 |
| 4 机 | **S-Robust** | **49.91** | **0.0%** | **49.41** |
| 5 机 | S-Reactive | 43.13 | 100% | 41.73 |
| 5 机 | S-Trust | 47.37 | 15.6% | 41.73 |
| 5 机 | **S-Robust** | **49.12** | 15.1% | **44.23** |

**关键结论（鲁棒性）：**
1. **"完全信任预警"有尾部风险**——S-Trust 在预警到达时表现很好，但**漏报（15%）的场景仍会崩溃**：4/5 机故障崩溃概率仍达约 15%，与漏报率一致。这说明**预警不能作为唯一防线**。
2. **鲁棒策略以小代价换取尾部安全**——S-Robust 常备托底切负荷，使 4 机故障崩溃概率从 15.1%→**0%**，5 机故障 5% 尾部从 41.7→44.2 Hz 显著抬升。**用少量确定性代价（托底切负荷）对冲预警失效的灾难性尾部风险。**
3. **误报代价可控**——托底切负荷带来的误报代价 = 误报率 × 托底比例，远小于其规避的崩溃损失，风险收益比高。
4. **预警是"降本"而非"免责"工具**——预警的价值在于**减少常备托底切负荷的需求量**（把被动的大切负荷替换为预警触发的按需处置），但仍需保留与漏报率匹配的托底措施。

## 总体研究闭环（P0→P5）

```
P0 研究方案/建模规范/参数策略/场景矩阵
P1 SMIB 最小闭环: 市政断水→水位→跳泵→背压→跳机→频率  (机理贯通)

```

## 局限与后续
- **QSS + 简化频率模型**：一阶机理正确捕捉"速率/提前量竞赛"，但非逐周波机电暂态；RoCoF、暂态摇摆、电压动态需 ANDES/PSS-E RMS 增强。
- **备用/切负荷参数**为典型假设（三级备用 900 MW、~15 min 起机），绝对量值供参考，**相对趋势与临界结论稳健**。
- **预警可靠性已建模（本扩展）**：漏报/时延抖动/误报下的鲁棒策略已量化；后续可做参数化敏感性（不同漏报率下的最优托底比例）与形式化的风险-代价优化。
- **可扩展维度**：断水速率（渐变 vs 突变）、多机跳机间隔、环境高温共因、网络 N-1 叠加，均可纳入更高维韧性图谱。
