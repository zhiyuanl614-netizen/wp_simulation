# P1 — SMIB 最小闭环仿真

**阶段目标：** 在单机—系统等值（SMIB 型）框架上打通"市政水网故障 → 水源侧水位下降 → 循环水泵流量下降/汽蚀跳泵 → 凝汽器背压上升 → 高背压保护跳机 → 系统频率响应"的**完整机理链条**，验证四层耦合模型（W→A→B→C）的时序因果关系。

## 文件

| 文件 | 说明 |
|---|---|
| `params.py` | 参数模块。无现场数据 → 按标准 + 机组额定/实际出力（读 `ieee118_dc/gen.csv`）拟合；含水蒸气饱和线 Antoine 公式 |
| `submodels.py` | 四层子模型：W 水力 / A 凝汽器‑低压缸 / B 机电（受影响机组 + 系统其余部分，COI 频率） |
| `simulate.py` | 仿真驱动。统一显式积分打通全链条，事件触发跳泵/跳机/UFLS |
| `plot_results.py` | 结果可视化，输出 6 联图 |
| `../results/*.csv` `../results/*.png` | 仿真输出 |

## 运行

```bash
cd p1_smib
python simulate.py --t_fault 60 --ramp 0   --t_end 2400   # S01 市政断水阶跃
python simulate.py --t_fault 60 --ramp 600 --t_end 3000   # S02 市政供水渐降(600s)
python plot_results.py                                     # 绘制 results/ 下所有结果
```

参数：`--t_fault` 故障时刻(s)，`--ramp` 市政补水衰减时间(s，0=阶跃)，`--bus` 选取 IEEE118 机组母线（默认 89，最大机组），`--dt` 步长。

## 模型链条与关键机理

```
市政断水 Q_make→0
  └─[W]→ 补水箱快速放空(~1min) → 集水池缓慢下降(损失得不到补充)
       └─ 集水池跌破低水位 → 循环水泵流量降额→汽蚀→跳泵(m_cw→0)
            └─[A]→ 换热能力骤降 → 凝汽器背压飙升(ε-NTU)
                 └─ 背压≥跳机定值+延时 → [B] 机组跳闸
                      └─ 有功缺额 → COI 频率跌落 → 系统备用一次调频/UFLS → 频率恢复
```

**关键时序量：缓冲时间 t_buffer**（断水→跳机）由"补水箱+集水池可用蓄水量 / 循环损失率"决定，是留给应急处置的窗口。

## P1 初步结果（机理验证，bus89: Pg=607/Pmax=707 MW）

| 场景 | 市政故障形式 | 泵跳闸 | 机组跳闸 | 缓冲时间 | 频率最低点 |
|---|---|---|---|---|---|
| S01 | 阶跃断水 (ramp=0) | ~1380 s | ~1280 s | ~1320 s (~22 min) | 49.54 Hz |
| S02 | 渐降 (ramp=600 s) | ~2327 s | ~2226 s | ~2267 s (~38 min) | 49.54 Hz |

**观察：**
1. **链条贯通且时序合理**——水力(分钟级)→热力(秒级)→机电(秒级)多时间尺度衔接正常。
2. **故障发展速率影响缓冲时间**——市政供水渐降使缓冲窗口从 ~22 min 延长到 ~38 min，为应急处置争取时间；但一旦跳机，频率冲击深度相近（取决于机组出力占比，与断水速率关系弱）。
3. **系统备用决定频率能否恢复**——单机跳闸后，系统其余部分的旋转备用与一次调频把频率从 nadir 拉回稳态；若备用不足或多机共因跳闸，将触发 UFLS 甚至欠频崩溃（P3/P4 在 IEEE 118 上重点考察）。

## 说明与局限（P1 定位）
- SMIB 用"受影响机组 + 系统其余部分等值"近似，用于**机理验证**，非精确电网响应；精确的潮流/电压/联络线级联留待 P3 在 IEEE 118 + ANDES(RMS) 上实现。
- 参数为标准/典型值拟合，绝对量值供参考，**相对趋势与因果时序**是本阶段结论重点。
- 背压在跳机瞬间的短暂非单调（先升→微降→随泵跳骤升）源于热负荷随出力下降与流量下降的竞争，属可解释的建模细节。
- 下一步（P3）：将本套水力‑热力子模型作为"外部功率降额/跳机信号源"接入 IEEE 118 的 RMS 动态仿真，考察真实网络的潮流转移、电压与级联。
